# 錢脈

> 更新於 2026-10-02：PC 本機版已具備聯絡人、聯絡追蹤、紀錄計分及週／月報。完整行程與後台仍在補齊，手機測試暫緩；最新狀態見第二十五節。

## 啟動 PC 預覽

在專案終端執行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\dev.ps1
```

等待終端機顯示 `Waiting on http://localhost:8081`，再開啟 http://localhost:8081 。終端機需保持開啟，按 Ctrl＋C 停止；重新開機後需重新啟動。前端通常自動更新，後端程式或 migration 修改後須重新啟動。

WSL 使用現有 Windows 環境啟動：

```bash
cd /mnt/d/insurance-crm-app
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'D:\insurance-crm-app\scripts\dev.ps1'
```

先註冊測試帳號（姓名、Email、密碼），或使用本機 seed 帳號。需要初始化管理員時執行 `powershell -ExecutionPolicy Bypass -File .\scripts\dev.ps1 -Task db:seed`；既有帳號不重設密碼。憑證保存在 Git 忽略的 `.data/dev-accounts.txt`，不得貼入 README 或提交版本庫。

資料預設存於 `.data/development.sqlite`，可透過環境設定更改；目前沒有上傳雲端，請使用假資料測試。

其他電腦需先安裝 Node.js 24 LTS，執行 `npm ci`、`npm run dev`。詳細結構、已完成與未完成範圍見 [實作架構](docs/architecture.md)，驗證結果見 [測試紀錄](docs/testing.md)。

**錢脈**是一款以**行事曆**為核心，整合聯絡人管理、客戶追蹤、未定行程與業務計分的業務管理 App。

產品主要面向台灣業務人員，希望透過簡單直覺的操作方式，協助使用者管理人脈、安排業務行程、維持客戶聯絡頻率，並透過清楚的成果回饋，提高持續使用與完成業務目標的動力。

# 一、專案背景

業務人員在日常工作中，需要持續管理大量客戶、潛在客戶與業務行程。

常見需求包含：

* 管理聯絡人
* 記錄客戶資訊
* 管理客戶重要程度
* 維持固定聯絡頻率
* 記錄與客戶的互動
* 安排下一次聯絡
* 管理每日行程
* 保存尚未確定日期的事項
* 追蹤每日或週期性的業務目標

目前市面上已有相關業務管理工具，但部分產品功能較多、操作較複雜，並非所有功能都符合實際業務工作的需求。

因此，本專案希望建立一套：

> **簡單、快速、以行事曆與人脈管理為核心的業務管理工具。**

# 五、App 主要架構

登入後進入「主頁／我的一天」，顯示今日得分、累計總分、聯絡安排與月曆。

主畫面底部固定為：**計分卡｜分級｜主頁｜聯絡人｜未定行程**，主頁在正中間。未定行程有未完成事項時，右上角顯示紅色數字徽章；零筆隱藏，超過 99 筆顯示 99+。

聯絡人新增／編輯是完整頁面，不是小視窗；頁內底部為 **分級｜主頁｜紀錄**，此處主頁是聯絡人基本資料。上方「儲存」才提交變更，成功後留在原頁；有未儲存修改時返回，跳出繼續編輯／放棄修改並返回的確認視窗。分頁切換保留草稿。

管理員登入後另有「管理後台」入口，一般使用者不顯示。

* 建立或修改行程

## 6.2 月曆顯示

目前已接上聯絡人的首次與下次聯絡安排，日期顯示筆數，下方列出當日行程；獨立多筆自由行程仍待實作。

### 顯示範圍

* 日期格只顯示筆數，下方列表顯示當日全部行程（已確認）
* 下方顯示完整當日列表，日期格不塞入行程文字
* 獨立週視圖不在本期
* 以月曆下方當日列表作為每日查看入口
* 推播不在本期；目前紅點僅為 App 內提醒

# 八、客戶分級

已確認預設等級與聯絡間隔：

| 等級 | 聯絡間隔 |
| --- | --- |
| A | 1 週 |

A、B、C 的聯絡間隔固定，不可修改或刪除。使用者可自行新增自訂名稱等級，並設定各自的聯絡間隔。自訂名稱為 1–20 字元，可用 AA、VIP 或中文，首尾空白移除、英文轉大寫，不可重複；可修改間隔，仍被任何聯絡人使用時不能刪除。月份按日曆月計算，月底無對應日期時取該月最後一天；計算細節與預設等級規則見 [需求規格](docs/requirements.md)。

# 九、聯絡頻率與安排

* 首次聯絡依建立日期（台灣時間）加上分級間隔安排；未分級不自動安排。
* 每次新增聯絡紀錄或完成聯絡，都需重新確認分級，沿用原等級也必須明確選取。未選仍可保存內容與計分，但列入「待重新分級」，不沿用舊分級安排日期。補分級後依該次聯絡日期加分級間隔安排下次。完成聯絡表單可一併選級與調整建議日期。
* 儲存時一起保存紀錄、計分與下一次安排；下次日期須晚於完成日期，也可留空進入未定清單。
* 「重新安排日期」保存原日期與新日期歷史，不新增聯絡分數。
* 「撤銷最近一次安排」按逆序恢復原日期；若撤銷的是完成聯絡，也移除該次紀錄並撤銷分數。
* 已明確安排的日期不會因分級間隔變動而自動重排；修改一般紀錄也不會重排，需使用「聯絡安排」。
* 目前每位聯絡人維持一個下一次安排；獨立多筆自由行程仍待實作。

# 十、聯絡紀錄

手動紀錄欄位為 **日期、內容、計分項目（可不計分）**，日期預設台灣今天；不另要求聯絡方式、備註、下一步等欄位。

* 編輯聯絡人 → 紀錄 → 新增紀錄，填寫後按上方「儲存」才保存；分頁切換不自動儲存。
* 每筆手動紀錄可編輯與刪除，刪除需確認。聯絡人詳情也可直接查看、編輯及刪除已保存紀錄，不必進入編輯聯絡人頁。
* 詳情頁的「儲存紀錄／確認刪除」直接提交該次操作；編輯聯絡人頁內則統一由上方儲存提交。
* 建立聯絡人後，自動顯示建立日期紀錄。依目前決定保留，不提供編輯或刪除。
* 姓名、分級與其他聯絡人資料不會因修改紀錄而被自動重設。

---

# 十一、未定行程

與主頁日曆分開，包含以下部分：

1. **到期未完成月曆**：今天及過去尚未完成的聯絡安排，按原安排日期顯示紅色數字，點日期看下方列表。未來安排仍在主頁查看。
2. **尚未安排日期**：在聯絡安排中明確留空日期的聯絡人，另列清單，不放入日期格。

3. **待重新分級**：已保存新的聯絡紀錄，但尚未重新確認等級；列在未定清單並計入底部紅點，補分級後移除。歷史舊紀錄不自動追補此狀態。

底部未定徽章加總各類，每位聯絡人不重複計數。封存聯絡人不計入提醒。點項目可進入聯絡人詳情，完成聯絡、重排或撤銷；新日期保存後更新日曆與紅點。新帳號的未分級聯絡人，不因沒有自動日期就一律視為未定事項。

目前以上以聯絡人追蹤為範圍，尚未提供獨立無客戶的自由事項。

# 十二、計分卡

**計分卡只能查看，不能登記、編輯或撤銷分數。** 計分從聯絡紀錄選項目並儲存，或完成聯絡流程一起產生。

## 12.1 計分規則

| 項目 | 初始分數 |
| --- | --- |
| 聯繫 | 1 |
| 接觸 | 5 |
| 活動 | 5 |
| 看店 | 8 |
| 深度面談 | 10 |
| 上卡 | 40 |

分數由後端提供，已保存項目保留當時名稱及分數。後台修改分數的 API 已有，操作表單尚未完成。

* 分數無上限、跨日累積；40 是上卡單次分數，不是滿分或每日目標。
* 紀錄與計分在同一交易保存；重複儲存同一紀錄不會重複加分。
* 修改紀錄內容不重算歷史分數；修改日期會移動計分日；改計分項目依當前規則重算。
* 刪除紀錄或改為不計分會撤銷對應分數，累計排除已撤銷項目。
* 過去未選計分項目的紀錄不自動補分。

## 12.2 週報／月報

老闆在管理後台設定全站週期，預設週報（週一至週日），可改為月報（每月一日至月底）。使用者選日期後，顯示該期範圍、分數、有效行動筆數、分類統計及明細；另外保留每日得分與累計總分。

結算不歸零、不設上限。目前報表是即時統計，修改舊紀錄會更新歷史報表；鎖帳、封存報表及定時寄送尚未提供。

# 十三、成果回饋與使用動力

採用溫暖綠金配色、每日成果摘要與清楚的操作回饋，不做角色養成或遊戲系統。每日得分與跨日總分無上限，不設定 40 分滿分或達標進度。

計分卡只能查詢，聯絡紀錄選擇計分項目並儲存後才計分；刪除紀錄會撤銷分數。後台可決定週報或月報，結算不清除累計總分。

# 十四、帳號註冊與權限

註冊必填 **姓名（1–80 字元）、Email、密碼（12–128 字元）**。其他帳號個人欄位目前未增加。自行註冊是否開放由後端設定，正式環境預設關閉。

每位使用者的聯絡人、安排、紀錄與計分各自隔離。一般帳號不可直接查閱或修改他人資料，管理員與授權讀取由後端檢查權限。

**填寫 Email 不代表已完成信箱驗證。** 驗證信／驗證碼、重寄與有效期、忘記密碼、重設密碼、更換信箱及正式邀請均尚未實作。曾討論以驗證連結起步，但尚未接寄信服務；既有測試帳號不可當成已驗證信箱。

# 十五、資料授權

目前需求包含使用者之間的資料授權機制。

例如：

```text
使用者 A
    │
    │ 授權
    ↓
使用者 B
```

授權後：

```text
B 可以查看 A 的資料
B 不可以修改 A 的資料
後台管理帳號可以修改
```

因此權限概念至少包含：

```text
自己的資料
├── 查看
├── 新增
├── 修改
└── 刪除

被授權的其他使用者資料
├── 查看
└── 不可修改
```

目前僅提供授權／撤銷及 workspace 唯讀存取 API；完整共享資料與計分查看介面尚未完成。

* 可以取消授權
* 需要授權紀錄

# 十九、資料安全與隱私

錢脈預期可能處理：

* 姓名
* 電話
* Email
* 生日（及保留的舊版重要日期）
* 聯絡紀錄
* 人際關係資訊
* 客戶分類
* 行程
* 業務備註
* KPI 資訊

因此資料安全屬於核心需求。

基本原則：

* 使用者必須經過身分驗證
* 不同使用者資料必須隔離
* 資料存取必須經過權限檢查
* 被授權資料應遵守 Read-only 等權限限制
* 客戶資料不得公開存取
* 測試期間不得任意使用真實客戶資料
* 正式環境與開發環境應適當區隔
* 敏感資訊不得直接寫入程式碼
* Backend 必須實作正式授權機制

正式上線前，應另外確認台灣個人資料保護及相關法規要求。

## 23.3 每日工作方式

1. 確認當日交付物，拆成能在當天驗收的小任務。
2. 從 `develop` 建立 `feature/*` 或 `fix/*`，完成介面與資料串接。
3. 檢查正常操作、空資料、輸入錯誤、失敗提示與權限；關鍵規則補自動化測試。
4. 通過檢查後提交並整合，更新排程、阻礙與下一步。
5. 新需求先記入待辦；若納入本期，同時調整範圍或工期。

已確認採用 **PC 瀏覽器為主要確認方式；手機測試目前暫緩，先補齊 PC 功能**。技術選型必須支援 PC 預覽；手機階段檢查觸控、鍵盤、返回與版面差異，交付前完整驗證 Android 與 iOS。各功能檢查點見 [需求規格](docs/requirements.md)，第一個功能的操作情境見 [使用流程](docs/user-flow.md)。
