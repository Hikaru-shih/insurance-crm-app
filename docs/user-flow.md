# 使用流程與業務規則

更新：2026-09-22。使用者指定以最新 README 為準；下列分為已實作流程與後續實作基準。

## 已實作：登入與聯絡人

登入／建立測試帳號 → 行事曆首頁 → 新增聯絡人 → 姓名（必填）＋性別／IG／群組／備註／生日（選填）→ 儲存成功關閉表單 → 聯絡人列表 → 詳情 → 編輯。

* 姓名空白／生日無效：顯示原因，保留輸入。
* 群組可多個，以頓號或逗號分隔；儲存移除空字串及重複標籤。
* 新增成功後列表可查到；IG、姓名及群組可搜尋。重載或重新登入讀回 Backend 資料。
* 儲存中不重複送出，Backend revision 比對防止同版本重複覆寫。
* 未儲存離開提示放棄／繼續編輯。儲存錯誤保留表單；版本衝突需取消並重載，再套用修改。
* 登出先讓 Backend 撤銷 token，再卸載帳號畫面；登入過期也移除舊畫面。切換帳號重新載入，不共用前帳號資料。
* 舊本機資料須主動匯入全新空白帳號；原始檔與已停用欄位保留。不自動把重要日期猜成生日。

## 後續行程與聯絡流程基準（尚未實作）

聯絡人詳情 → 新增行程 → 自填顯示標題、日期／時間、顏色 → 有日期進月曆，無日期進未定行程。

* 只填標題即可建立未定事項；客戶選填，以支援會議等事項。
* 過期判定以 Asia/Taipei 的日期為準：排程日期早於今天且未完成，列為逾期；不因今天某時刻剛過就移走。
* 狀態：未排程／已排程／已完成。逾期為已排程未完成的衍生標記，不額外複製資料。
* 重排修改同一行程的目前日期，保留首次排程日期與每次改期歷史。
* 完成時填實際完成日期及可選的計分行動；有客戶互動才新增聯絡紀錄，不把每個會議都當聯絡。
* 聯絡紀錄至少包含客戶、實際聯絡日期、方式及內容，下一步選填。
* 下次建議日＝實際聯絡日＋等級間隔；月份取日曆月，月底不足取最後一天。需使用者確認才建下次行程，不修改已確認的其他行程。
* 每一行程最多一筆有效積分；完成同一行程重送不加分，分數保存當時規則快照。
* 撤銷完成保留歷史並沖回原分數；重新完成按新的完成操作建立紀錄，舊紀錄標撤銷，不與舊分數累加。補登歸屬實際完成日期，未來日期不可補登。
* 每日目標先採後台全體預設 40 分；不回算過往已保存的分數。個別目標與 Streak 留後續。
* 刪除聯絡人採封存基準：從一般列表隱藏，保留已關聯行程／紀錄，避免歷史孤立。硬刪除及復原介面另定；目前尚無刪除入口。
* 未定入口分尚無日期／逾期未完成，完成後不再列入；先按原始日期、無日期者按建立時間排序。

## 授權與管理

本人指定對象 → Backend 建唯讀授權並留紀錄 → 對方 API 可讀不可寫 → 本人撤銷 → 下一次讀取被拒絕。分享不轉授權。管理員可修改其他人的聯絡人並留紀錄，不因角色而開放尚未定義的代新增／刪除。

上述授權與管理修改 API 已測試，完整分享與管理修改畫面尚未完成。已提供管理員帳號清單與操作紀錄頁。

## 驗收方式

PC 先確認畫面與正常／失敗流程，每個完整功能完成後再 Android 手機驗證。鍵盤、返回與觸控需實機檢查；iOS 尚待設備及簽章條件。詳細見 release.md。
